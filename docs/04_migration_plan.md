# 04. 기초재고 마이그레이션 방안

## 0. 재고 마이그레이션이 일반 데이터 이행과 다른 점

| 일반 마스터/거래 이행 | 기초재고 이행 |
|---|---|
| 원천 테이블 → 타겟 테이블 매핑 | **원천이 여러 개, 계산 결과**가 타겟 (세관재고·수불·교환권 조합) |
| 언제 돌려도 결과 동일 | **시점 의존**. 영업 마감 후 동결 시점에만 정확 |
| 건수 대사로 검증 | **수량 대사**(창고×상품 단위) + 실사/세관재고와 비교 |
| 재실행 쉬움 | 오픈 후엔 신규 시스템 수불이 쌓이므로 **틀리면 되돌리기 어려움** |

따라서 핵심은 ① 규칙을 고객과 **표로 확정**하고, ② 각 구성요소를 **따로 적재(컴포넌트 테이블)** 해서 어디서 차이가 났는지 추적 가능하게 하고, ③ **리허설을 최소 2~3회** 돌려 대사하는 것.

## 1. 고객 규칙 정리 (매트릭스)

| 재고구분 | 본점 | T1-DF4 / T2-DF4 | 통합물류 |
|---|---|---|---|
| **상품 기초** | HS세관재고 집계 (환급코드 분리 → 집계, 구코드 정리) | HS세관재고 집계 (환급코드 분리, 구코드 정리) | **계산재고** = 수불 기말재고 **+** 교환권 판매수량 **−** H신고 재반입면장 교환권(미취소) 판매수량 |
| **GWP 기초** | 계산재고 | 수불재고 | 계산재고 |
| **미인도 기초 (상품·GWP)** | **−** 미인도반입면장 교환권(미취소) 판매수량 | 없음 | **−** 미인도반입면장 교환권(미취소) 판매수량 |

용어:
- **교환권(+)**: (빌상태, 상품위치) ∈ {(00 매출, 02 통물창고), (00 매출, 12 통물미래보세), (01 면장등록, 12 통물미래보세)} — 팔렸지만 아직 통물에 실물이 있는 것.
- **H신고 재반입 교환권(−)**: WM038 면장구분 05/75/85/10/80/90/20/91 (PROP_1='H') + G1 확정, 또는 5KP 반입신고(B/R) F1 결과통보.
- **미인도 반입 교환권(−)**: WM038 06/76/86 + G1 확정.

### 고객에게 확인할 해석 (Q&A 시트로 받기)
1. **H신고 재반입분을 왜 빼는가?** 재반입 시 수불에 이미 반입(+)으로 잡혀서 교환권(+)과 이중이 되기 때문인지 — 이 해석이 맞다면 차감 대상은 "교환권(+) 집합에도 속하는 빌"인지, 전체인지.
2. **미인도 "−"의 의미**: (a) 미인도 기초재고 = 해당 수량 (별도 재고유형으로 적재) 이면서 정상재고에서 차감, 인지 (b) 정상재고에서 차감만 하는 것인지.
3. **본점 GWP "계산재고"** 공식이 통물과 동일(수불 + 교환권 − H재반입)한지. 교환권 위치코드가 본점이면 01 점창고/11 점미래보세 등 다른 조합인지.
4. "수불 **기발**재고" = **기말**재고 오타로 보임. 수불 원천은 **WM0053L(물류 월별수불내역, 월 단위)** 로 확인. WM0054L 은 폐기신고라 수불이 아님 → 일반상품/GWP 및 일별 수불 테이블 재확인.
5. WM0121S 에는 상품코드·HS코드가 없음(확인) → 상품별 세관재고는 **WM0121L 반입−반출 합계**로 산출, WM0121S 는 보세구역 합계 대사용. WM0121L 이력 완전성 확인 필요.
6. **환급코드 분리** 기준 컬럼(WM0121L.CSTM_ITEM_CLS_CD? PMIT_CLS_CD 91 국산비환급?)과 환급↔비환급 상품코드 매핑표.
7. **구코드 정리** 매핑표 (구상품코드 → 신상품코드, N:1 허용 여부).
8. 점코드 매핑: 본점 / T1-DF4 / T2-DF4 / 통합물류 각각의 STOR_CD, 재고코너(STOC_CORN_CD: 965, 961, 813 …) ↔ 신규 시스템 창고코드.
9. 부분취소/부분반품(SA0103D.RTN_QTY, SALE_CNCL_YN) 처리 방식.
10. 기준일시(Cut-off): 예) 오픈 D-1 영업마감 + 세관 EDI 수리 마감 시각.

## 2. 전체 흐름

```
[사전]  코드/매핑표 확정 ─ 점·창고 매핑, 구코드 매핑, 환급코드 매핑
          │
[동결]  영업 마감 / 세관 EDI 수신 마감 / 수불 마감 배치 완료 확인  (BASE_DT 확정)
          │
[추출]  컴포넌트별로 MIG_STOC_COMP 에 적재 (sql/02~05)
          ├ C01 HS세관재고          (본점, T1, T2 상품)
          ├ C02 수불기말재고         (통물 상품, 전점 GWP)
          ├ C03 교환권 (+)           (통물 상품·GWP, 본점 GWP?)
          ├ C04 H신고 재반입 (−)     (통물)
          └ C05 미인도 반입 (−)      (본점, 통물)
          │
[변환]  환급코드 분리 → 구코드 매핑 → 점/창고 매핑
          │
[집계]  MIG_BASE_STOC = SUM(SIGN × QTY) GROUP BY 창고, 상품, 재고유형
          │
[검증]  sql/07 대사 쿼리 (음수, 미등록상품, 컴포넌트 합계, 세관재고 vs 계산재고)
          │
[적재]  신규 시스템 기초재고 테이블 (타겟 스펙 받아서 매핑)
          │
[사후]  오픈 후 D+1 재고 실사 샘플 / 세관재고 대사
```

### 3-2. 스테이징 (sql/01_staging_ddl.sql)
- `MIG_STOC_COMP` : 컴포넌트 상세 (원천 키 BILL_NO 등을 남겨서 건별 추적 가능)
- `MIG_BASE_STOC` : 최종 기초재고
- `MIG_MAP_STOR`, `MIG_MAP_GOOS`, `MIG_MAP_REFUND` : 매핑표
- 모든 행에 `MIG_RUN_ID`(리허설 회차)를 넣어 회차별 비교

### 3-3. 컴포넌트 추출 원칙
- 원천 수량은 **부호 없이** 적재하고 `SIGN`(+1/−1) 컬럼으로 가감 → 대사가 쉬움
- 빌 기반 컴포넌트(C03~C05)는 **빌 키 DISTINCT → 상세 조인** 순서 (카톤 중복 방지)
- 판매취소 판정은 공통 로직 하나로 (기준일 이전 발생한 취소만, 날짜 무관)
- 재고 귀속 창고는 `SA0103D.STOC_STOR_CD / STOC_CORN_CD`

### 3-4. 변환 순서 (고객 지시: "환급코드 먼저 반영후 집계")
1. **환급코드 분리** — 상세 레벨(WM0121L 등)에서 환급/비환급 속성으로 상품코드 분리. 집계 후엔 속성이 사라지므로 반드시 집계 전에.
2. **구코드 정리** — 구→신 코드 매핑 후 재집계 (N:1 이면 합산).
3. **점/창고 매핑**.

### 3-5. 검증 (sql/07_verify.sql)
| 검증 | 기준 |
|---|---|
| 컴포넌트별 합계 | 점 × 컴포넌트별 총수량을 고객에게 리포트, 사인오프 |
| 음수 재고 | 0건이어야 함. 발생 시 원천 빌 추적 |
| 미등록 상품 | 신규 상품마스터에 없는 GOOS_CD 0건 |
| 구코드 잔존 | 매핑 후 구코드 0건 |
| 중복 | 같은 빌이 C04/C05 에 중복 0건, C04 내 중복 0건 |
| 세관재고 대사 | 통물 계산재고 vs 통물 HS세관재고 차이 리스트 → 차이 원인 설명 가능해야 함 |
| 리허설 간 비교 | 회차별 차이 = 그 사이 영업 변동으로 설명 가능해야 함 |

## 4. 실무 주의사항

- **Excel로 내리지 말 것** (샘플에서 이미 발생): BILL_NO `5.26112E+14`, GOOS_CD `2.64608E+11` 로 깨지고, BO014 `'02'` → `2`, `'00'` → `0` 처럼 **앞자리 0이 사라짐**. 대사용 추출은 Toad의 *Export → Delimited(텍스트 따옴표)* 또는 DB 테이블로.
- 상태 컬럼(BILL_PROC_CLS_CD, GOOS_LOC_CLS_CD)은 시점 스냅샷 → **동결 후 즉시 추출**.
- 개인정보(PSPT_NO, CUST_NM, TEL_NO)는 재고 이행에 불필요 → 스테이징에 가져오지 않기.
- 이행 수행 스크립트, 실행 로그, 결과 건수/수량은 회차별로 보관(감리/세관 대응).
